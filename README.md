# Keyboard Mages

Браузерная PvP-игра: два игрока сражаются в дуэли 1v1, применяя заклинания через быстрый и точный
ввод слов-триггеров на клавиатуре.

Полное игровое и архитектурное описание — в [`game-design.md`](./game-design.md).

## Стек

- **Backend:** NestJS + Socket.IO, состояние боя — в памяти сервера (`backend/`)
- **Frontend:** Angular, standalone-компоненты, signals (`frontend/`)
- **Боевая сцена:** чистый CSS (спрайт-анимации через `background-position` + `steps()`), без Pixi/GSAP

## Структура репозитория

```
keyboard-mage/
├── game-design.md   # игровой дизайн, протокол, открытые вопросы
├── backend/         # NestJS-сервер (matchmaking, дуэли, заклинания, эффекты)
└── frontend/        # Angular-клиент (лобби, поиск матча, каркас боя)
```

## Backend

```bash
cd backend
npm install
npm run start:dev   # http://localhost:3000, WebSocket на том же порту
```

Модули: `SpellsModule`, `EffectsModule`, `DuelModule` (включает `DuelGateway`), `MatchmakingModule`.
Подробности протокола WebSocket-событий — в разделе 3 `game-design.md`.

## Frontend

```bash
cd frontend
npm install
npm start   # http://localhost:4200
```

Реализованы: главный экран со спеллбуком — выбор школы мага (иконки, `public/school-icons/`)
и просмотр её заклинаний (иконки, `public/spell-icons/`: название/описание/урон/эффект/кулдаун
при выборе), с крупной idle-анимацией выбранного мага справа. Выбор школы реально уходит в
`find_match` (`SocketService.findMatch`). Доступные школы — `fire`, `ice`, `arcane`, `chaos`,
`nature` (`MageType`, значения совпадают с backend `SpellSchool` дословно); иконки и данные
заклинаний готовы для всех 5 школ. Кнопки заклинаний в бою (`.spell-btn`) обведены цветом по
тиру: 1 — синяя, 2 — фиолетовая, 3 — золотая.

Дальше — лобби с поиском матча через `MatchmakingGateway` (`find_match` →
`queue_joined`/`match_found`) и боевая сцена с двумя анимированными бойцами по краям арены,
HP-баром над каждым (реально отражает текущее HP, не всегда полный) и idle/attack-анимациями
на спрайт-листах (`frontend/public/<mage-type>/`). При изменении HP (урон/хил, от любого
источника — прямой удар, DoT, отражение щитом) над персонажем всплывает и исчезает циферка.
В бою внизу экрана — панель реальных кнопок заклинаний школы игрока (иконка + горячая клавиша
`1..N`, обводка по тиру — синяя/фиолетовая/золотая), кнопка на кулдауне заблюрена с таймером
поверх; по нажатию открывается окно ввода триггера с полоской, отображающей реально оставшееся
время на каст (CSS-анимация, синхронизирована с серверным `deadline`, не тикает клиентски), ввод
посимвольно уходит на бэкенд (`cast_start`/`key_input`), результат (`spell_resolved`) закрывает
окно и проигрывает анимацию атаки. Всё это (HP/кулдауны/эффекты) синхронизируется через один
`player_sync` раз в тик
(бывший `effects_sync`); над персонажем при активных баффах/дебаффах показываются иконки
заклинания-источника с таймером (одна иконка на `sourceSpellId`, без объединения одинаковых).
Спрайт соперника соответствует реально выбранной им школе — сервер сообщает её в `match_found`
(`opponentSchool`). По окончании боя (`match_ended` — по HP <= 0 или дисконнекту соперника,
который автоматически засчитывает ему техническое поражение) — экран результата поверх
замороженной сцены: золотая «ПОБЕДА» или красная «ПОРАЖЕНИЕ» и кнопка «Вернуться на главную»,
сбрасывающая состояние матча и возвращающая на спеллбук. Оформление — светлая 8-bit-тема, шрифты
Press Start 2P
(заголовок/акценты) и JetBrains Mono (кириллица, UI-текст). Подключение к WebSocket —
`SocketService` (`frontend/src/app/socket.service.ts`), адрес backend захардкожен на
`http://localhost:3000`.

## Статус

Backend: базовый скаффолдинг всех модулей готов, все 25 заклинаний (5 школ × 5–6) реализованы
с полноценной системой эффектов (урон-диапазоны, DoT/HoT, щиты, отражение, death ward, общий
кулдаун по тиру школы и т.д.). Открытые вопросы дизайна и нерешённые механики — раздел 7 и 8
`game-design.md`.

Frontend: лобби, выбор школы (спеллбук со всеми 5 школами), реальный каст заклинаний
(кнопки/горячие клавиши/окно ввода/кулдауны на кнопках), визуальная боевая сцена (спрайты с
реальной школой соперника, реальный HP-бар, летающие циферки урона/хила, иконки активных
баффов/дебаффов над персонажем, анимации) и экран результата матча (включая техническое
поражение при дисконнекте соперника) готовы. Не хватает: серверного ограничения "какие
заклинания игрок может кастовать" по выбранной школе; грейс-периода на реконнект (сейчас любой
дисконнект в бою необратим).
